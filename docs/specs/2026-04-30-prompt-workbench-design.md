# 智能提示词工作台 — 设计规格文档

## 1. 产品定位

多人共享的提示词管理工具。用户可以集中存储、分类、搜索和复用提示词模板，解决提示词散落在笔记、文档、聊天记录中难以查找和复用的问题。

### 目标用户

内部小团队（3-10 人），通过共享密码访问，无需注册账号。

### 使用场景

- 教育内容生成（知识点梳理、出题）
- 工作文档处理（报告、总结、邮件）
- 图片生成（儿童绘本插图、科普配图）
- 开发辅助（代码生成、技术方案）
- 提示词优化（用元提示词生成更好的提示词）

## 2. 核心功能

### 2.1 提示词管理（CRUD）

- 新建提示词：填写标题、正文（Markdown）、选择大类、添加标签、定义变量
- 编辑提示词：修改任意字段
- 删除提示词：确认后删除
- 查看提示词：Markdown 格式化预览

### 2.2 分类与搜索

- 按大类筛选：生图 / 生文 / 分析 / 开发 / 元提示词（后续可扩展）
- 按标签过滤：点击标签快速筛选
- 关键词搜索：搜索标题和正文内容

### 2.3 变量模板

- 提示词正文中使用 `{{变量名}}` 定义占位符
- 使用时界面自动识别变量，展示填写表单
- 填入具体值后生成最终文本，一键复制到剪贴板
- 示例：`请梳理{{学科}}{{年级}}的核心知识点` → 填入"语文""八年级" → 生成最终文本

### 2.4 一键复制

- 查看提示词时，点击复制按钮将最终文本（含变量替换结果）复制到剪贴板
- 复制成功后给出视觉反馈

## 3. 数据模型

### 3.1 prompts 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键，自动生成 |
| title | text | 提示词标题，如"儿童绘本插图规范" |
| content | text | 提示词正文，Markdown 格式 |
| category | text | 大类：生图 / 生文 / 分析 / 开发 / 元提示词 |
| tags | text[] | 标签数组，如 ["儿童", "科普", "绘本"] |
| variables | jsonb | 变量列表，如 [{"name": "学科", "default": "语文"}] |
| created_by | text | 创建人名称 |
| created_at | timestamptz | 创建时间，自动生成 |
| updated_at | timestamptz | 更新时间，自动更新 |

### 3.2 变量校验规则

- 变量名不能为空，不能重复
- 正文中的 `{{xxx}}` 如果没有匹配的变量定义，使用时原样保留不替换
- 保存时用 Zod 校验变量格式

### 3.3 分类管理

大类列表以常量数组形式存储在前端代码中：`["生图", "生文", "分析", "开发", "元提示词"]`。数据库中 category 字段为自由文本，不做枚举约束，方便后续扩展新大类时只需修改前端常量。

### 3.4 Supabase 安全策略

使用 Vercel Serverless Function 做密码验证中间层：

1. 前端输入密码后，调用 `/api/verify` 接口验证
2. 验证通过后返回一个短期 token
3. 前端后续请求通过该 token 访问 Supabase（使用 service-role key 在 serverless function 中代理请求）
4. Supabase 的 anon key 不暴露给前端，数据库通过 RLS 禁止 anon 角色直接访问

这样即使有人查看前端源码，也无法绕过密码直接操作数据库。

## 4. 技术架构

### 4.1 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端框架 | React + TypeScript | 主流选择，类型安全 |
| UI 组件库 | Radix UI | 无样式基础组件，可访问性好 |
| 样式方案 | Tailwind CSS | 与 Radix UI 搭配，快速开发 |
| 数据校验 | Zod | 前端数据格式校验 |
| 后端服务 | Supabase | PostgreSQL 数据库 + 实时同步 |
| 部署 | Vercel | 静态站点托管，自动部署 |

### 4.2 架构图

```
用户浏览器
  ├── React SPA（Vercel 托管）
  │     ├── 密码输入 → 调用 Vercel Serverless Function 验证
  │     ├── 提示词管理界面
  │     └── 通过 Serverless Function 代理访问 Supabase
  │
  ├──→ Vercel Serverless Functions
  │     ├── /api/verify（密码验证，返回 token）
  │     └── /api/prompts（CRUD 代理，使用 service-role key）
  │
  └──→ Supabase
        ├── PostgreSQL（prompts 表，RLS 禁止 anon 直接访问）
        └── Realtime（多人实时同步，通过认证 token 订阅）
```

### 4.3 认证方案

- 不使用 Supabase Auth，不需要用户注册
- 共享密码存储在 Vercel 环境变量中（服务端，不暴露给前端）
- 前端输入密码后调用 serverless function 验证，通过后返回 session token
- 验证状态存入 sessionStorage，关闭浏览器标签页后需重新输入密码

## 5. 界面设计

### 5.1 整体布局

三栏布局：

```
┌──────────┬────────────────┬──────────────────────┐
│ 左侧导航  │   中间列表      │    右侧详情/编辑      │
│          │               │                      │
│ 大类筛选  │  提示词卡片列表  │  Markdown 预览        │
│ ·生图    │  - 标题        │  变量填写表单          │
│ ·生文    │  - 标签        │  一键复制按钮          │
│ ·分析    │  - 摘要        │  编辑/删除操作         │
│ ·开发    │               │                      │
│ ·元提示词 │               │                      │
│          │               │                      │
│ 搜索栏   │               │                      │
└──────────┴────────────────┴──────────────────────┘
```

### 5.2 页面列表

| 页面 | 说明 |
|------|------|
| 密码输入页 | 首次访问时展示，输入共享密码后进入主界面 |
| 主界面 | 三栏布局，提示词浏览、搜索、使用 |
| 新建/编辑弹窗 | 弹窗表单，填写提示词各字段 |

### 5.3 交互流程

1. 打开网址 → 输入共享密码 → 进入主界面
2. 左侧选择大类 → 中间列表过滤展示 → 点击某条 → 右侧展示详情
3. 右侧点击"使用" → 填写变量 → 一键复制最终文本
4. 点击"新建" → 弹窗填写表单 → 保存
5. 右侧点击"编辑" → 弹窗修改 → 保存
6. 右侧点击"删除" → 确认 → 删除

## 6. 非功能需求

- **响应式**：适配桌面端为主，移动端采用单栏布局 + 导航抽屉（左侧分类收起为汉堡菜单，列表和详情上下排列）
- **性能**：提示词数量预计 < 500 条，无需分页，前端全量加载即可
- **实时同步**：利用 Supabase Realtime 订阅 prompts 表全量变更，一人新增/修改后其他人自动看到更新
- **数据备份**：主界面左侧导航底部放置"导出数据"按钮，点击后将全部提示词导出为 JSON 文件下载
- **created_by 字段**：新建提示词时必填创建人名称，无默认值

## 7. 不做的事情（第一版）

- 不做 AI 模型调用和测试功能
- 不做用户注册和个人账号体系
- 不做提示词版本历史
- 不做提示词评分或收藏
- 不做待办跟踪
- 不做移动端专属 App 或独立的移动端设计（仅通过响应式布局适配）
